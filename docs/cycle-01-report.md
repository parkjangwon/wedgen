## 📊 각 역할별 현 상태 점검

### 1. 마케터 관점 분석 ✅

**강점:**
1. 기능적 차별점 분명: "로컬 실행 + 정적 ZIP + 즉시 배포"는 기존 SaaS와 차별화
2. 사용 흐름 명확: 템플릿 선택 → 입력 → 미리보기 → ZIP 생성
3. 템플릿 감성 다양성: 11개 템플릿으로 취향 대응력 확보

**개선점 (우선순위):**
1. **포지셔닝 메시지 기술 중심** → 감성 설득 약함
2. **첫 진입 전환 설계 부재** → 홈 랜딩 없이 에디터로 바로 리다이렉트
3. **핵심 가치 제안 미정리** → "왜 WedGen인지" 한 줄 요약 부재
4. **신뢰/안심 장치 미노출** → 로컬 처리, 복원 기능 등 안심 포인트 미강조
5. **컨버전 트리거 약함** → "3분 완성", "지금 샘플로 시작" 등 CTA 부족

**제안:**
- 포지셔닝: "우리 손으로 완성하고 바로 배포하는 로컬 모바일 청첩장 메이커"
- 브랜드 3축: `진심(감성)` + `주도권(로컬/수정)` + `실행력(즉시 배포)`

**비즈니스 강점:**

**전략적 과제 (중요도 순):**
1. **[핵심]** 타깃 고객·가격 포지셔닝 미정
2. **[핵심]** 배포/운영 허들 (비기술 사용자 진입 장벽)
3. **[중요]** 차별화 스토리 부족
4. **[중요]** 리텐션 구조 약함 (단발성 수요)
5. **[향후]** 운영 자동화·품질 지표 부재

**사업 방향성:**
- "한국식 모바일 청첩장 품질 1위"에 집중
- 2단계 GTM: 로컬-프로 사용자 → 원클릭 배포 대중 확대
- 수익모델: 템플릿 단건 + 프리미엄 번들 + 제작 대행

### 3. 백엔드 개발자 관점 분석 ✅

**기술적 강점:**
1. 책임 분리 우수: API 라우트 얇고, 로직은 lib으로 분리
2. 생성 파이프라인 실용적: tweak/optimized 모드, sharp WebP 변환, archiver ZIP
3. 기본 안정성: zod 검증, XSS 방어 escape, 에러 처리 존재

**개선점 (우선순위):**
1. **[높음]** SSRF/낶부망 접근 리스크 (`/api/validate`)
2. **[높음]** 입력 검증/경로 검증 부족 (경로 탐색 방어 필요)
3. **[중간]** 대용량 요청 시 메모리 과다 (버퍼 중첩)
4. **[중간]** 템플릿/썸네일 API 캐싱 비효율
5. **[낮음]** 에러 처리 표준화/관측성 부족

**개선 제안:**
- Zod 검증 계층 표준화
- `/api/validate` allowlist/DNS+IP 검사
- 스트리밍 기반 ZIP 응답으로 메모리 최적화
- 템플릿 캐시 전략 (LRU + mtime invalidation)

### 4. 디자이너 관점 분석 (Sisyphus 직접 분석)

**디자인 강점:**
1. 에디터 UI 전문성: 좌측 편집/우측 미리보기 SaaS 수준 구조
2. 미리보기 프레임 고급스러움: 다크 테마, 디바이스/백드롭 선택, 줌 기능
3. 템플릿 CSS 체계화: CSS 변수 기반 테마 시스템 (--wedgen-*)

**디자인 문제점 (심각도 순):**
1. **[심각]** 템플릿별 시각적 차별화 부족 - 대부분 비슷한 구조
2. **[심각]** 청첩장 결과물의 "돈 주고 살 만한" 프리미엄 느낌 부족
3. **[보통]** 에디터 폼 UI가 일반적, 프리미엄 SaaS 수준 미달
4. **[보통]** 애니메이션/인터랙션 단조로움 (fade/slide만)
5. **[경미]** 컬러 스킴 선택 폭 제한 (3개)

**디자인 개선 제안:**
1. 템플릿별 고유한 레이아웃 패턴 도입 (Hero 중심형, 스크롤 스토리형, 카드형 등)
2. 고급 템플릿용 프리미엄 디자인 요소 (패럴랙스, 마이크로 인터랙션)
3. 에디터 폼 UI 고급화 (섹션별 아이콘, 진행 상태 시각화)
4. 다양한 애니메이션 옵션 추가 (페이지 트랜지션, 요별 등장)

### 5. 프론트엔드 개발자 관점 분석 (Sisyphus 직접 분석)

**코드 강점:**
1. React 19 + Next.js 16 최신 스택 활용
2. TypeScript 타입 안정성 확보
3. Tailwind CSS v4 + shadcn/ui 일관된 디자인 시스템
4. EditorLayout 809줄의 복잡한 상태 관리가 useDeferredValue로 최적화

**코드 개선점 (우선순위):**
1. **[높음]** EditorLayout 809줄 - 과도한 책임, 분리 필요
2. **[높음]** localStorage 기반 저장 - 동기화 이슈, 용량 제한
3. **[중간]** 템플릿 스크립트 중복 - 각 템플릿마다 유사한 JS
4. **[중간]** 이미지 최적화 클라이언트 사이드 부재
5. **[낮음]** 웹 워커 미활용 - 메인 스레드 블로킹 가능성

**개선 제안:**
1. EditorLayout 분해: DraftProvider, PreviewPanel, EditorPanel로 분리
2. IndexedDB 기반 저장으로 전환 (용량, 구조화 데이터)
3. 템플릿 공통 JS 유틸리티화 (renderers 공통화)
